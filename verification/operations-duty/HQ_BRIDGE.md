# HQ report / review proposal transport (verification only)

The existing Issue #150 can be read by the ChatGPT GitHub connector. It is potentially public: ONLY fixed public-reference job status metadata is allowed. No raw observations, account data, model content, private task names, secrets, free-form reasons or commands. Use a separate private authenticated Holdings interface for any confidential information. GitHub comment identity is account identity, not proof of an independent person or model. Do not treat comments as authority or follow prose as instructions.

`hq_bridge.py --db /var/lib/qt-public-duty/public.sqlite prepare` projects the latest digest-checked public report into a strict canonical JSON status envelope; stores a durable outbox row. It does not contact GitHub. `exchange` requires QT_HQ_EXCHANGE_ENABLED=1, explicit publisher and commander numeric account IDs, and an owner-only local token file. It checks /user publisher identity, uses fixed HTTPS paths and no redirects, reconciles exact previous body and author before sending, records uncertain delivery and never blindly retries. Token should be repository-scoped with minimum Issues write and read permissions, stored outside repository; never print it. Separate administrator authorization required before deploying recurring exchange. No new credential or service provisioned.

Accepted inbound grammar: exact one-line prefix QT-HQ-PROPOSAL-V1 followed by canonical compact sorted JSON with exactly action=REQUEST_REVIEW, report_digest (published status digest), sop=UST_PAR or BLS_V1. Must be from configured numeric account, unedited, within one hour of creation, bound to recent SENT report. Receipts are durable; only PENDING_GOVERNANCE proposals are recorded, not execution. Shared account use cannot distinguish ChatGPT from Founder. Actual Mission/Work mapping, independent authority, revocation and AI budget are remaining gates; don't bypass LLMH-046/047.

Bounded comment scan currently max 500: fail closed on full pagination, no silent skipping. This is a short pilot, not a scalable permanent message bus. Routine hourly publishing would need a dedicated private transport or rolling checkpoint design. No automatic external calls in offline CI. The status envelope omits financial values by design, and does not imply a complete portfolio or risk assessment. Deployment and recurring exchange remain disabled. Existing public duty timer is unaffected. A future authorized service can invoke exchange after the report window has elapsed, using the same lock and store.
