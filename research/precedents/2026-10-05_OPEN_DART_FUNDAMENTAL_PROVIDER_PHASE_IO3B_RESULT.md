## 1. Purpose

IO-3A created a provider-neutral point-in-time fundamental evidence contract.

IO-3B binds the first real external provider behind that contract:

**Financial Supervisory Service Open DART**

This does not make DART authoritative for investment decisions.

It makes DART a bounded external information provider whose output must still
pass Thesis / Portfolio / Risk / Committee governance.

## 2. Official API contract used

The adapter follows the Open DART developer guides for:

- corporation-code archive:
  `https://opendart.fss.or.kr/api/corpCode.xml`
- disclosure search:
  `https://opendart.fss.or.kr/api/list.json`
- single-company full financial statements:
  `https://opendart.fss.or.kr/api/fnlttSinglAcntAll.json`

The financial endpoint requires:

- API key;
- corp_code;
- business year;
- report code;
- financial-statement scope.

The adapter supports the documented report codes:

- `11013` — first quarter;
- `11012` — half year;
- `11014` — third quarter;
- `11011` — annual report.

The disclosure-search request deliberately uses:

`last_reprt_at=N`

so corrected/amended filings remain visible for revision detection instead of
silently requesting final-only history.

## 5. Corporation-code resolution

KRX ticker input:

```text
KRX:005930
```

is resolved through the official `corpCode.xml` archive.

The adapter:

1. downloads the zip;
2. parses the contained XML;
3. maps six-digit `stock_code` to eight-digit DART `corp_code`;
4. caches the mapping in memory for the provider instance.

No ticker/corp-code mapping is hard-coded into investment logic.

## 6. Financial-statement scope

Default scope:

`CFS` — consolidated financial statements.

Optional fallback:

`OFS` — separate financial statements.

The fallback is explicit in `DartProviderConfig`.

The selected scope is preserved in every observation ID and normalization
method so CFS and OFS values cannot be silently mixed.

## 7. Metric identity

Known XBRL account IDs are mapped to stable QuanTrade metric bases where safe:

- `ifrs-full_Assets` → `TOTAL_ASSETS`
- `ifrs-full_Liabilities` → `TOTAL_LIABILITIES`
- `ifrs-full_Equity` → `TOTAL_EQUITY`
- `ifrs-full_Revenue` → `REVENUE`
- `ifrs-full_ProfitLoss` → `NET_INCOME`
- `dart_OperatingIncomeLoss` → `OPERATING_INCOME`

Unknown standard account IDs are preserved as DART-scoped identities rather
than guessed from Korean account names.

Every normalized metric also preserves:

- statement division (`BS/IS/CIS/CF/SCE`);
- current-period vs current-YTD amount field;
- CFS/OFS scope.

Example:

```text
OPERATING_INCOME:IS:CURRENT_PERIOD
```

## 8. Publication-time policy

Open DART disclosure search exposes `rcept_dt` as a filing **date**.

It does not provide an intraday timestamp in this API response.

QuanTrade therefore applies a conservative rule:

```text
DART filing date
→ 23:59:59 Asia/Seoul
```

and marks:

`published_at_precision = DATE`

This prevents a historical Case at noon on the filing date from assuming that
the report was already available.

## 9. Critical historical-correction rule

The full-financial endpoint is queried by company/year/report/scope and returns
a receipt number.

A dangerous situation exists when:

1. an original filing existed before a historical Case;
2. a correction was filed later;
3. the current financial endpoint exposes the later corrected receipt/data.

Using that corrected value in the earlier Case would create look-ahead.

IO-3B detects this situation by comparing:

- the financial endpoint receipt;
- all periodic filings from `list.json`;
- normalized original/correction report families;
- the requested Case as-of.

If an earlier filing was available by `as_of` but DART's current financial
endpoint exposes only a later correction, the provider raises:

`DartPointInTimeUnavailable`

with the required remediation:

**XBRL-by-receipt parsing**

It does not silently:

- use the corrected number;
- use today's value;
- drop the revision and pretend the Case is complete.

This is intentionally fail-closed.

## 10. Revision metadata

When a correction is validly available by the requested Case as-of, the
observation preserves:

- correction receipt number as `revision_id`;
- previous matching receipt as `revision_of`;
- `restated = true`.

The source document receipt number is also retained independently.

## 11. Amount parsing

The adapter handles:

- comma-formatted numeric values;
- negative parenthesis notation;
- blank / unavailable amount fields;
- current-period amount;
- current cumulative/YTD amount.

It does not add together ambiguous duplicate XBRL rows.

If the same normalized statement/account/amount identity appears twice, the
first provider version fails closed rather than choosing one dimension/member
arbitrarily.
