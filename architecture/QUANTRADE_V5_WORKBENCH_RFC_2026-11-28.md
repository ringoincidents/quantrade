# QuanTrade v5 — Investment Workbench transition RFC
2026-11-28 | Founder requested development start | PROPOSED / draft review; does not silently supersede canonical 2026-10-04 vision.

## Purpose
Move repeated real investment work from chat into durable, reproducible software. Keep Private Investment Office as North Star; v5 is delivery architecture, not a new company. Mobile report-first, manual execution first, deterministic-first, evidence and uncertainty explicit. No live order, deployment, paid storage, private data or existing scheduler changes in this PR.

## Responsibility vs implementation
Founder/CIO owns mandate and approvals. Client Intelligence/Strategy owns private IPS and capital constraints. Investment Research owns company/valuation, macro/sector and technical diagnosis. Portfolio Management owns sizing and alternatives. Risk independently checks/vetoes; cannot originate sizing. Committee/Decision Management records proposal, approval, timing and invalidation. Operations handles reconciliation, monitoring and later execution. Performance & Learning owns prediction/outcome records. Quant Research Lab is isolated: G0 data, registered hypothesis, exploratory test, independent out-of-sample, shadow, approval, ongoing monitoring. Model validation independent of model authors.
Shared infrastructure (not departments): Data Vault, security master, evidence/provenance, calculation library, private persistence, job scheduler, model gateway, audit/authority, backup.
Components: price/FX adapters, statement normalizer, valuation models, technical calculators, macro checklist, sector cycle classifier, portfolio calculator, risk rules, rule evaluator, report renderer. Services/workflows compose components: opportunity screening, position monitoring, investment case review, daily report, research validation. UI: Today, Portfolio, Company/Research, Decisions, Lab. One modular Python app initially; private database/backend later. No microservice or per-department agent by default.

## Delivery slices (acceptance)
S0 this draft: explicit observation + manually approved valuation target -> deterministic entry-condition report, synthetic examples only. Input source, timestamp, currency, target version, expiry and stale cutoff; missing/stale/currency mismatch fail closed; no buy recommendation. Tests and CLI. Adapter contract provisional, later map to #119/#140.
S1 review #119/#120/#138/#140 and write migration manifest; pick one source of truth, public-data adapter and private store. Import approved watchlist/valuation snapshots; closed-session data and provenance, idempotent daily run, stale/missing reason, audit record. Existing alerts kept until parity and explicit cutover. Acceptance: compare existing alerts over >= 10 trading sessions, investigate discrepancies, zero unlabelled stale/missing; no claim of predictive accuracy.
S2 private portfolio ledger + manual CSV import, reconciled cash/positions/FX, target bands and independent limits; transaction/correction audit. Add mobile Today/Portfolio pages and authenticated access; compare against broker statement; no public data leakage.
S3 company analysis: reuse approved DCF/sector models, scenario/sensitivity, evidence refs; research case, thesis/risk/decision/monitoring links. Screen only eligible coverage. Macro and technical deterministic reports separate from unvalidated predictive models.
S4 research outcome ledger and promotion registry; validate QT-TE/MRI/sector projects after point-in-time data gate. AI for unstructured interpretation and counter-research only, budget/latency logged; trigger on material changes. Manual order preview and read-only broker integration later after approvals.
S5 execution optional, separately authorized and gated; audit, idempotency, reconciliation, kill switch, no LLM direct orders.

## User interface
Today = data as-of/health, changes since last review, current entry checks, risk flags, action inbox (not ticker dashboard). Portfolio = cash/currency/holdings/target vs actual/limits; Company = dated valuation scenarios, inputs, evidence, technical diagnosis, thesis and revisions; Decisions = proposal, approval or reject/defer, plan, due date and actual result; Lab = research status/data gate/negative results, not trading signals. Read-first mobile layout, details on demand. Compare against GPT session: single source of truth, incremental computation, saved versions, reproducible report, daily schedule and no repeat prompt. Measure manual review time, data coverage/stale rate, discrepancies, AI cost per useful case and user follow-up. No guaranteed profitability.

Historical data and private runtime access remain blockers. Existing strategy gates remain binding.
