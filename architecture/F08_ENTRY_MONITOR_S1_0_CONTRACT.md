## Chosen contract (S1.1 local/manual only; version entry-monitor-v1)
Single monitoring projection of an independently approved valuation snapshot, not a canonical investment/thesis model. Map to approved valuation producer later. Store decimal strings (no float conversion); timestamps ISO8601 with offset; immutable input IDs.
Target: instrument (exchange-qualified security identifier, not company name), currency, value (positive per-share), margin (fraction 0<=m<1), version, evidence reference, approval reference, approved_at, expires_at, invalidated_at or null, price_basis (raw same share basis), state (APPROVED/REVOKED). Require explicit private operator approval, not a boolean supplied by an untrusted client. Only one current approved version per instrument. Target and its approval cannot be inferred from chat or draft config.
Quote: instrument, currency, price (positive unadjusted regular close per share), source/provider, source reference, session_date (exchange local), observed_at (verified exchange session close instant), retrieved_at, available_at (known availability; do not invent provider publication time), finality (FINAL or UNKNOWN), price_basis, revision, rights reference when live. Manual pilot explicitly labels MANUAL, synthetic labels SYNTHETIC; neither implies verified live data. Store correction versions, never overwrite.
Run: run_id, schema/version, mode, expected session per market, as_of, started/finished timestamps, input references, status/reason per target, output values and errors; deterministic rerun for same inputs; one logical result per instrument/session/target version/quote revision; append audit without duplicate alert. Public repo only fictitious fixtures.
Policy: per-market exchange calendar, timezone, actual close including early close. Expected session is most recent completed regular session at run time; if provider not yet published, report pending/BLOCKED, do not silently substitute earlier close. Holidays/weekends use latest valid session, never arbitrary 24h freshness. Explicitly distinguish collected_at/available_at from close. Raw price/share basis must match approved value; split/revision/known material event or expired/revoked target blocks until reapproval. Unknown corporate-action/finality/identity or stale/missing quote blocks. S1.1 manual expected session and verified finality are operator declarations for local test only; S1.2 requires calendar/provider validation.
Comparator: entry=V*(1-m); actual margin=1-P/V; gap to entry=(P-entry)/entry; positive gap is above threshold, negative below. No rounded display value used for comparisons. REVIEW if P<=entry with all preconditions met; WAIT if P>entry; BLOCKED for missing/invalid/ambiguous/stale inputs. REVIEW means threshold check, not BUY, prediction or order. Keep status and reason separately.
Report: one row per enabled instrument, status/reason, actual close and currency, threshold, gap, session; source and target version/expiry in detail. Review first, blocked next, wait by proximity; stable tie-break by instrument. Health distinguishes job state from data freshness; no invented live indicator. Private local report, export/import, no public hosting or raw user data.
S1.1 minimum acceptance: synthetic and manually entered 2–3 fictitious instrument fixtures; test threshold equality, holiday/early-close expected-session cases supplied manually, wrong currency, missing/stale/unknown quote, revoked/expired/duplicate approval, basis mismatch, exact decimal arithmetic; atomic private local persistence/export and no network/order; report accessible in local browser/mobile layout; failure visible. Do not treat as live operation.
S1.2: choose lawful regular-close provider per enabled market, demonstrate finality/actual calendar/price basis and permitted storage; no paid subscription without budget approval. Existing Naver/Yahoo/Stooq cannot be promoted solely because code exists. S1.3: private authenticated report + scheduling, >=10 trading sessions parity with same legacy inputs; explain all discrepancies, no unlabelled stale/missing, retain existing alerts until explicit cutover.
